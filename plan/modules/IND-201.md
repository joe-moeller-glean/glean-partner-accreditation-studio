## 1. Narrative frame

- **Recurring persona:** Dana and Alex running an accelerator studio
- **Through-line situation:** Turning a repeated vertical workflow into a reusable agent accelerator the practice can resell
- **Cold open (A1) hook:** Dana's team has built the same claims-triage agent four times. The fifth time should take a day.
- **Signature moment (one T3 reveal):** Accelerator assembles: workflow, agent pattern, governance, and packaging lock into a reusable asset

## 2. Learning outcomes (observable)

- `OBJ-01` — Identify a vertical workflow worth productizing as an accelerator
- `OBJ-02` — Design the accelerator with configurable boundaries
- `OBJ-03` — Package governance, documentation, and handoff for reuse
- `OBJ-04` — Validate the accelerator against a second customer's constraints

## 5. Interactions

- **`INT-SIM`** — Three studio sequences: build core, parameterize, validate against a second customer.
- **`INT-TRACE`** — Validation against a second customer's constraints - the signature lock-in.
- **`INT-SORT`** — Components classified as configurable or intentionally fixed.
- **`INT-FADE`** — Governance and documentation packaging.
- Keyboard-equivalent path required in every component; state persisted to `cmi.suspend_data`; restores exactly on resume.

## 6. Assessment plan

- **Format:** Capstone lab (tracker: `Capstone lab`)
- **Blueprint:** Verifiable end state: a working accelerator with a configuration surface, governance package, documentation, and evidence it works for a second constraint set. Rubric-scored across completeness, reusability, governance, and documentation.
- **Mastery:** 80%, retries reshuffled, explanatory feedback on final attempt
- **Distractor sources:** Embedded checks target: hard-coding customer specifics, packaging without governance, validating against only one customer.
