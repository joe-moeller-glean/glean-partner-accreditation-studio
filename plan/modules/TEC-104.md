## 1. Narrative frame

- **Recurring persona:** Sam with Northwind's network team
- **Through-line situation:** The crawl fails silently and nobody can tell whether it is DNS, proxy, or allowlisting
- **Cold open (A1) hook:** Day four of the deployment. The crawl reports success and indexes nothing. Three teams each believe it is someone else's layer.
- **Signature moment (one T3 reveal):** Data path illuminates one segment at a time until the failing hop is isolated

## 2. Learning outcomes (observable)

- `OBJ-01` — Specify allowlisting, proxy, and DNS requirements for a deployment
- `OBJ-02` — Choose an appropriate private connectivity approach for a constrained network
- `OBJ-03` — Trace a data path to isolate a connectivity failure
- `OBJ-04` — Produce a network readiness runbook

## 5. Interactions

- **`INT-TRACE`** — Learner reads a diagnostic trace table and isolates the failing hop; keyboard table navigation, selection persisted.
- **`INT-BRANCH`** — Private-connectivity approach selection for a constrained network.
- **`INT-SORT`** — Symptoms mapped to the network layer that causes them.
- **`INT-HOTSPOT`** — Data path hops.
- Keyboard-equivalent path required in every component; state persisted to `cmi.suspend_data`; restores exactly on resume.

## 6. Assessment plan

- **Format:** Quiz, 8 items (tracker: `Quiz`)
- **Blueprint:** OBJ-01 x2, OBJ-02 x2, OBJ-03 x3 (diagnostic reasoning), OBJ-04 x1.
- **Mastery:** 80%, retries reshuffled, explanatory feedback on final attempt
- **Distractor sources:** Blaming DNS for an authorization failure, assuming allowlisting is bidirectional, assuming a successful crawl report means indexed content.

## 7. Job aid / carry-away

- Network readiness runbook with the diagnostic decision tree and the required allowlist entries.

## 8. Claims to establish and verify

- Actual connectivity requirements, IP/egress specifics, and supported private connectivity options - tier-1 product docs only
- Crawl and webhook behavior relevant to diagnosis
- Any specific IP range or hostname must be sourced and re-verified at 90 days

Freshness window: 90 days (product configuration). Network specifics change without notice.. Every factual sentence carries a `claim_id` resolving to `sources.json`.

## 9. Risks, blockers, and SME questions

- Publishing stale IP ranges or hostnames actively breaks deployments; treat every specific value as a 90-day claim with a named owner.
- `Content Requests` source with no asset - net-new from product documentation.
- Required for the Solution Architect badge.
- No owner - `needs_sme`.
