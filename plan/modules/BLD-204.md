## 1. Narrative frame

- **Recurring persona:** Alex implementing the embedded experience
- **Through-line situation:** Build a working embedded search and an API-backed flow
- **Cold open (A1) hook:** The SDK renders in five minutes. Making it respect permissions, handle empty states, and survive a token refresh takes the rest of the lab.
- **Signature moment (one T3 reveal):** The embedded experience runs correctly for two different users with different permissions

## 2. Learning outcomes (observable)

- `OBJ-01` — Implement an embedded experience with the Web SDK
- `OBJ-02` — Implement an API-backed flow with correct authentication
- `OBJ-03` — Handle permissions, empty states, and token lifecycle
- `OBJ-04` — Test the integration against two different user contexts

## 5. Interactions

- **`INT-SIM`** — Four lab sequences: embed, authenticate, verify permissions across two users, handle edge cases.
- **`INT-SORT`** — Defects matched to causes.
- **`INT-CHECKLIST`** — Environment check and the two-user test checklist.
- Keyboard-equivalent path required in every component; state persisted to `cmi.suspend_data`; restores exactly on resume.

## 6. Assessment plan

- **Format:** Lab (tracker: `Lab`)
- **Blueprint:** Verifiable end state: working embedded experience, authenticated API flow, correct results for two different permission contexts, handled empty and expiry states. Rubric-scored.
- **Mastery:** 80%, retries reshuffled, explanatory feedback on final attempt
- **Distractor sources:** Embedded checks target: testing with one user only, ignoring token refresh, treating an empty result as an error.
