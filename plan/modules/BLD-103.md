## 1. Narrative frame

- **Recurring persona:** Alex in a hands-on workshop
- **Through-line situation:** Build a working action and an MCP-backed flow in one session
- **Cold open (A1) hook:** By the end of this lab you will have a working action calling a real endpoint - and you will have broken it twice on purpose.
- **Signature moment (one T3 reveal):** The completed flow runs end to end and the trace confirms each step

## 2. Learning outcomes (observable)

- `OBJ-01` — Build and configure a working custom action
- `OBJ-02` — Connect an agent to an MCP-backed tool and verify the call path
- `OBJ-03` — Diagnose and fix a failing tool call
- `OBJ-04` — Document the build so another engineer can maintain it

## 5. Interactions

- **`INT-SIM`** — Four guided lab sequences with per-step verification; step state persisted so a mid-lab resume lands correctly.
- **`INT-TRACE`** — Read the call trace and confirm each hop.
- **`INT-SORT`** — Errors matched to causes.
- **`INT-CHECKLIST`** — Environment prerequisite check before the lab starts, and the documentation template after.
- Keyboard-equivalent path required in every component; state persisted to `cmi.suspend_data`; restores exactly on resume.

## 6. Assessment plan

- **Format:** Lab (tracker: `Lab`)
- **Blueprint:** Verifiable end state: a working action, a connected MCP tool, a successful trace, and a completed documentation artifact. Rubric-scored on completeness, accuracy, fault diagnosis, and documentation quality.
- **Mastery:** 80%, retries reshuffled, explanatory feedback on final attempt
- **Distractor sources:** Embedded checks target: skipping the environment check, assuming a 200 response means correct behavior, undocumented auth configuration.

## 7. Job aid / carry-away

- Build documentation template plus an error-to-cause quick reference.

## 8. Claims to establish and verify

- Every lab step must match the current product UI and API surface - highest capture-staleness risk in the portfolio
- Lab environment prerequisites and access requirements
- Error messages and their real causes

Freshness window: 90 days, and re-verify after any relevant product release.. Every factual sentence carries a `claim_id` resolving to `sources.json`.

## 9. Risks, blockers, and SME questions

- Required for the Builder badge.
