## 1. Narrative frame

- **Recurring persona:** Dana with Alex the builder
- **Through-line situation:** An industry-specific agent that must respect a regulated workflow
- **Cold open (A1) hook:** The agent Dana designed would work perfectly - and would violate the customer's approval policy on step three.
- **Signature moment (one T3 reveal):** Agent design resolves: the workflow gains an approval gate and a scoped data boundary without losing its value

## 2. Learning outcomes (observable)

- `OBJ-01` — Design a vertical agent from a real industry workflow rather than a generic template
- `OBJ-02` — Scope agent data access to the workflow's governance requirements
- `OBJ-03` — Place approval gates where the industry requires human judgment
- `OBJ-04` — Validate an agent design against industry constraints before build

## 5. Interactions

- **`INT-FADE`** — Two-stage agent design from a real workflow.
- **`INT-SORT`** — Data sources sorted into in-scope / out-of-scope for the workflow's governance requirements.
- **`INT-BRANCH`** — Approval-gate placement - the signature resolve.
- **`INT-SIM`** — Constraint validation walkthrough.
- Keyboard-equivalent path required in every component; state persisted to `cmi.suspend_data`; restores exactly on resume.

## 6. Assessment plan

- **Format:** Design submission, rubric-scored (tracker: `Design submission`)
- **Blueprint:** Learner submits a vertical agent design: workflow mapping, scoped data access, approval gates, and a constraint validation checklist.
- **Mastery:** 80%, retries reshuffled, explanatory feedback on final attempt
- **Distractor sources:** Embedded checks target: designing from a template instead of a workflow, over-scoping data access, omitting approval gates in regulated steps.

## 7. Job aid / carry-away
