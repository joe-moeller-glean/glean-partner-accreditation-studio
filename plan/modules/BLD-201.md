## 1. Narrative frame

- **Recurring persona:** Alex, taking on a custom connector
- **Through-line situation:** A source with no native connector, an unstable API, and a customer expecting search results
- **Cold open (A1) hook:** The API returns 200 with an empty body under load. Alex's connector reports success and indexes nothing.
- **Signature moment (one T3 reveal):** Connector architecture resolves with failure modes handled at each stage

## 2. Learning outcomes (observable)

- `OBJ-01` — Choose a connector architecture for a given source and its API characteristics
- `OBJ-02` — Design authentication, schema mapping, and permission propagation
- `OBJ-03` — Handle rate limits, pagination, and partial-failure modes
- `OBJ-04` — Define the governance and handoff requirements for a production connector
