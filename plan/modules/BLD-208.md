## 1. Narrative frame

- **Recurring persona:** Alex and Sam together, before production
- **Through-line situation:** An agent with write access to a customer system and no approval design
- **Cold open (A1) hook:** The agent can close tickets. Nobody decided who is accountable when it closes the wrong one.
- **Signature moment (one T3 reveal):** Governance envelope closes around the agent: scope, approval, audit, and escalation each seal

## 2. Learning outcomes (observable)

- `OBJ-01` — Design safety and scope boundaries for a production agent
- `OBJ-02` — Place approval gates and define escalation paths
- `OBJ-03` — Specify audit and accountability requirements
- `OBJ-04` — Produce a production readiness review for a partner-built agent

## 5. Interactions

- **`INT-SORT`** — Actions sorted by whether they require human approval.
- **`INT-BRANCH`** — Approval placement and an unexpected-behavior response, both with real accountability consequences.
- **`INT-HOTSPOT`** — The four governance layers.
- **`INT-CHECKLIST`** — Production readiness review the learner completes.
- Keyboard-equivalent path required in every component; state persisted to `cmi.suspend_data`; restores exactly on resume.

## 6. Assessment plan

- **Format:** Scenario review, rubric-scored (tracker: `Scenario review`)
- **Blueprint:** Learner submits a production readiness review: scope boundaries, approval gates, audit requirements, escalation path, and a named failure scenario with its response.
- **Mastery:** 80%, retries reshuffled, explanatory feedback on final attempt
- **Distractor sources:** Embedded checks target: relying on prompt instructions as a boundary, no audit trail, escalation without an owner, approving by default.

## 7. Job aid / carry-away

- Production readiness review template with the four governance layers.

## 8. Claims to establish and verify

- Available guardrail, approval, and audit mechanisms - tier-1 docs; do not imply controls that do not exist
- What is logged and retained for agent actions
- Cross-reference TEC-102 security controls without restating them unverified

Freshness window: 90 days (security and governance posture).. Every factual sentence carries a `claim_id` resolving to `sources.json`.
