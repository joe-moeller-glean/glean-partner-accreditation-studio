## 1. Narrative frame

- **Recurring persona:** Alex, building something a customer will depend on
- **Through-line situation:** A multi-step agent with memory, tool selection, and a reusable pattern
- **Cold open (A1) hook:** Alex's agent works on the demo question and fails on the second one. The difference is composition, not prompting.
- **Signature moment (one T3 reveal):** Agent composition resolves: steps, memory, and tool selection assemble into a reusable pattern

## 2. Learning outcomes (observable)

- `OBJ-01` — Compose a multi-step agent with appropriate step types
- `OBJ-02` — Manage agent memory and context across steps
- `OBJ-03` — Design tool selection so the agent chooses correctly
- `OBJ-04` — Extract a reusable pattern from a working agent

## 5. Interactions

- **`INT-SIM`** — Three lab sequences: compose, add memory, fix tool selection.
- **`INT-FADE`** — Pattern extraction, worked then independent - the signature assembly.
- **`INT-SORT`** — Step types matched to tasks.
- **`INT-HOTSPOT`** — Step type reference.
- Keyboard-equivalent path required in every component; state persisted to `cmi.suspend_data`; restores exactly on resume.

## 6. Assessment plan

- **Format:** Lab (tracker: `Lab`)
- **Blueprint:** Verifiable end state: a working multi-step agent with memory, correct tool selection, documented test cases, and an extracted pattern entry. Rubric-scored.
- **Mastery:** 80%, retries reshuffled, explanatory feedback on final attempt
- **Distractor sources:** Embedded checks target: over-prompting instead of composing, no memory strategy, tool descriptions too vague for correct selection, no test cases.
