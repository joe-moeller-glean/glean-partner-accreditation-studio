# Module build contracts 01 — Foundations, Sales & GTM, Solutions & Value

For every entry, execute the source/claim, explanation, visual, practice, accessibility, QA, and release protocol in volume 00. **R/T/V/P/X** means research; ordered teaching sequence; visual/capture; performance evidence; and cross-module update. Exact UI names, claims, economic terms, and screenshots are research targets, not established facts. Local absence means no source in this repo, not proof that a partner LMS asset does not exist. Rebaseline time with a pilot instead of silently exceeding the roadmap. Module IDs/titles/statuses come from the 83-row [Module Tracker](https://docs.google.com/spreadsheets/d/16BS8Y4vawNmNqHJaRY5izRZUGhx_O_14jQefb6ifZ8Q).

## Solutions & Value — seven modules

### SOL-101 — Department & Persona Outcome Mapping · Refresh needed; local absent

- **T:** 1. Identify a real task and decision per persona. 2. Map task → sources → access → current failure → desired outcome → owner. 3. Compare executive sponsor, practitioner, admin and compliance perspectives. 4. Validate cross-department dependencies and a no-fit case.
- **V:** Persona-to-workflow/data map with example evidence and a conflicting-access overlay; screenshot of a cleared representative workflow only if current UI matters.
- **P/X:** Build two persona outcome maps with a source inventory and validation questions; rubric tests measurability and access. FND-106 owns discovery framing; DEP-* applies the map in eight specific functions; SOL-102 scores opportunities.

### SOL-102 — Use Case Discovery & Prioritization · Planned; local absent
- **R:** Source official service methodology and current prioritization template; interview delivery/solution SMEs on feasibility, user reach, data quality, security, change effort, and expected value. Mark any scoring weights as studio guidance unless approved.
- **T:** 1. Create candidate use-case cards from interviews. 2. Identify dependencies and blockers. 3. Score value, effort, readiness, risk with explicit assumptions. 4. Run sensitivity analysis where weights change. 5. Sequence pilot, later wave, and reject/defer with named evidence gaps.
- **V:** Transparent weighted matrix with worked calculation and dependency DAG; annotated example contrasting a tempting high-value but unsafe use case.
- **P/X:** Rank six unfamiliar cases and defend the top two to a skeptical panel; submit assumptions and a discovery backlog. SAL-202 captures opportunity evidence, SOL-103 values it, SRV-105 facilitates workshop dynamics.

### SOL-103 — Value Engineering & ROI Modeling · Planned; local absent
- **R:** Collect approved value-model template, measurement definitions, baseline gathering method, analytics access, adoption confounders, and legal-approved case studies. Validate model limitations and avoid universal productivity multipliers.

Connect source/agent capability to a measurable change. 5. Set instrumented pilot and post-launch review.
- **V:** Causal tree from behavior → usage → outcome → financial impact with confidence bands; fully worked spreadsheet-style example with formulas and red flags.
- **P/X:** Repair a flawed ROI model with double-counting and unrealistic utilization; submit an assumption register and measurement plan. SAL-201 borrows approved numbers only; SRV-201/202 collect realized data.
